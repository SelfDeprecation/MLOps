# MLOPS-26 — домашние работы 1–4

Репозиторий последовательно дополняется по заданиям курса. Код и отчёты
предыдущих работ сохранены; DVC-пайплайн доведён от сбора данных до готовых
для обучения токенизированных тензоров.

## ДЗ 1 — окружение и бенчмарк

- `make generate` — детерминированная генерация;
- `make bench` — измерение загрузки, скорости генерации и памяти;
- `docs/hardware.md` — профиль машины, результаты и разбор дефектов ДЗ 1.

## ДЗ 2 — параметры, хуки, LoRA и память

Скрипт `src.inspect_model`:

1. строит таблицу параметров по типам модулей с корректным учётом tied
   embeddings;
2. снимает нормы активаций первого, среднего и последнего decoder-блоков и
   удаляет forward-хуки после прогона;
3. сравнивает собственную формулу числа LoRA-параметров с `peft` для двух
   конфигураций;
4. измеряет пик памяти для инференса, полного fine-tune и LoRA, запуская каждый
   режим в отдельном процессе и выбирая метрику под устройство;
5. формирует `docs/anatomy.md`, `docs/activations.png` и служебный
   `docs/report.json`.

Заполненная вручную сводная таблица сдаётся как
`docs/anatomy-worksheet.xlsx`.

## ДЗ 3 — собственный датасет и DVC

Авторский русскоязычный набор диагностических вопросов по эксплуатации
MLOps-систем строится локально из рецензируемого каталога
`src/dataset_catalog.py`. DVC-пайплайн выполняет строгую проверку схемы,
маскирование PII, точную и приближённую дедупликацию, diversity-гейт и
групповой split без контаминации.

- v1: 1201 очищенный пример, 50 тем;
- v2: 1681 очищенный пример, 70 тем;
- train/val/test v2: 1345/168/168 строк, пересечения всех типов равны нулю;
- `docs/datasheet.md` — паспорт набора;
- `docs/defects.md` — разбор пяти намеренных дефектов стартового проекта.

## Запуск

```bash
uv sync
make generate
make bench
make inspect
make repro
make v1
make v2
make contamination
make check
```

Все настройки модели и измерений находятся в `params.yaml`. Для текущей
машины выбран `Qwen/Qwen3-0.6B`, `device: auto` и `float32`: процессор
Intel Core i5-8250U не ускоряет BF16, а 24 ГиБ RAM достаточно для замеров.

`make check-hw3` проверяет ДЗ 3; регрессионная самопроверка ДЗ 2 сохранена как
`make check-hw2`. Данные не попадают в Git: DVC хранит их в локальном
`dvc_remote/`, а Git отслеживает только код, метрики и `dvc.lock`.

## ДЗ 4 — токенизация и подготовка к обучению

Стадия `tokenize` применяет chat template Qwen3 одним общим путём для обучения
и инференса, маскирует промпт значением `-100`, использует динамический левый
padding и сохраняет статистику длин, обрезки и packing.

- train: 1345 примеров, 290296 токенов, из них 169309 попадают в loss;
- p50/p90/p99/max: 215/268/282/294 токена;
- при `max_seq_len=384` обрезано 0% примеров;
- packing уменьшает оценку числа шагов с 169 до 125 (-26%).

```bash
make tokenize
make check       # актуальная проверка ДЗ 4
make check-hw3   # регрессия ДЗ 3
```

Автоматически сформированный отчёт находится в `docs/tokenize_report.md`.
